# Upstream and sibling assessment — September 5, 2026

This is a dated source inspection, not a compatibility test report. No Huginn runtime has
been built. Keep this snapshot immutable when a later baseline is assessed; link the new
assessment from the README and record which integration tests actually passed.

## Pi baseline

The inspected sibling `../pi` is at **v0.85.0**, commit
[`107d79f11072bbc8a3a757ed7fd69596bee7d68c`](https://github.com/earendil-works/pi/tree/107d79f11072bbc8a3a757ed7fd69596bee7d68c),
released [September 4, 2026](https://github.com/earendil-works/pi/releases/tag/v0.85.0).
The package engine is Node `>=22.19.0`. Treat this as the initial investigation baseline,
not a tested Huginn-supported range or an assertion about future latest releases.

The previous Huginn proposal described v0.84.2, protocol v1, `PiServerService`, a missing
real session adapter, and an additive protocol v2. That is no longer the implementation
starting point. The new foundation moves business semantics into application services.

| Area | Observed at v0.85.0 | Consequence for Huginn |
| --- | --- | --- |
| Protocol | Version **8**; routed server/session/attachment identities; correlated opaque strict-JSON service payloads; cancellation; bounded CBOR framing | Use its routed envelope. Define product DTOs in application services, not new v2 commands. Raw byte arrays are not permitted inside its strict-JSON payloads. |
| Chord | Owns service contracts/catalogues, remote bindings, subscription snapshots/updates, replicated-state sequencing and gap handling | Reuse its hydration and replication behavior rather than maintaining a second generic session reducer. |
| Server | `Server`, `ServerListener`, routed service hosts/session handles, Unix transport, multiple presentation attachments | Assess a WebSocket listener and authenticated host composition against these interfaces. The old “only a service test stub exists” gap is obsolete. |
| Client | `Client`, `ByteTransportFactory`, service transport adapter, route validation, reconnect primitive; no automatic reconnect/replay | Add browser transport and reconnect orchestration; recover application receipts explicitly. |
| Session services | `SessionDirectory`, `SessionManagement`, `Models`, `AgentController`, and `Transcript` implementations in coding-agent experimental sources | Reuse creation/attachment/control/state where exposed; verify a public import/composition path before depending on source internals. |
| TUI | Experimental `pi client` uses the service runtime and worker-owned lane; multiple presentations are supported | Make same-session TUI/mobile handoff an early integration test. Existing code does not prove full stable-TUI/extension feature parity. |
| UI hooks | Experimental `PresentationUI` is process-local selection/status; broader UI examples are not built-in remote services | Approval/input bridging, reconnect-visible decisions, and Enclave attendance are concrete remaining gaps to assess. |
| Operation identity | `AgentController` returns operation/queue IDs and aborts by operation ID | Map receipt and run status to durable upstream evidence; inspect crash windows before asserting redispatch safety. |
| Authentication | Peer auth and authenticated service contexts are not supplied by the experimental transport | Huginn supplies operator/device authorization, trusted proxy handling, and shared control policy. |
| Compatibility | Protocol is explicitly experimental with no compatibility guarantees | Pin and test supported combinations; do not build legacy v1 projections speculatively. |

### Enclave contracts and gaps

The [configuration model](https://github.com/frycm/pi-enclave/blob/5cb03468b6e258b636c061229a38338616cbc97e/README.md#configuration-sources)
and its `src/config/{schema,types,merge,sources}.ts` own the boundary format. User-global
configuration is under the pi agent directory; project sources are constrained by its
monotonic fold. Models must not edit or replace this policy through Huginn. There is no
second Huginn rulebook.

The existing approval channel uses legacy extension UI requests: a session-start HMAC
attendance challenge, followed by UI confirmations. The channel handshake is not per-action
authentication. A host bridge must preserve genuine human attendance across PWA suspension,
disconnect and device handoff, not assert it because a daemon remains connected.

Persisted pending actions are approved by the standalone `pi-enclave approve <nonce>`
terminal command. No remote pending-action approval API exists in the inspected contract.
Some actions also have command-line resume limitations. Huginn needs an Enclave-owned
remote decision/resume interface before promising that flow from a phone; private file edits
or scripted terminal approval are not substitutes.

`src/gate/provenance.ts` treats `interactive` and `rpc` input as direct user input and
`extension` input as derived. Sending manager-generated text as ordinary RPC user input can
therefore give it the wrong authorization provenance. Verify an adapter that preserves the
original user intent separately from manager text before enabling this autonomous combination.

### Muninn contracts and gaps

Muninn already defines logical project UUIDs, canonical Git-common-directory/worktree
resolution, bounded explicit journal tools, and source/trust/correction provenance. Use its
supported interfaces when enabled; do not create another journal or modify its registry.
Huginn's operational IDs remain stable with an explicit mapping to Muninn project IDs.

The `pi-muninn/integration` export and `muninn ingest` support bounded external observations.
The custom-entry discriminator is `muninn-integration-v1`. An observation has schema `1`,
type `note`/`checkpoint`/`outcome`, bounded body/channel/tags/paths, and an integration block
including provider, kind, event, external ID and observed timestamp. The host can use provider
`pi-huginn`. Muninn assigns journal identity and `source: "external"`; producers cannot claim
user authority. Input is capped at 1 MiB/100 observations, and `(provider, external_id)` is
the deduplication key. Ordinary RPC-hosted session capture already exists; additional
observations must contribute new provenance rather than duplicate normal outcome capture.

The headless interface avoids loading the extension into Huginn's pi worker, but does not
by itself prove that all referenced pi formats or imports work on v0.85.0. A compatibility
test is still required. Journal export failure cannot block live session control.

## Next evidence to collect

1. A clean-install, real-worker composition smoke test using supported exports, including
   no-model observation and two simultaneous presentations.
2. Browser bundling/transport and bounded transcript behavior on the selected services.
3. Common-host receipt, takeover, one-writer and operation-recovery behavior under disconnect
   and process death; distinguish existing guarantees from required application additions.
4. Actual Enclave hooks and execution coverage in the selected runtime; human attendance,
   pending-action bridging, and manager provenance tested end to end.
5. Muninn's version update or supported headless combination, ordinary capture, explicit
   query, correction labels, and idempotent external observations.

The outcome is a small capability matrix and a concrete patch list, not an assumption that
all integrations work because their packages share the pi name. No upstream or sibling
repositories were modified as part of this documentation update.
